# TeXWeave v0.2.5 Update Plan

## 1. Version Goal

v0.2.5 focuses on introducing the first complete version of **basic LaTeX completion/autocomplete**.

The goal of this release is not to build a new LaTeX language engine from scratch. Instead, TeXWeave should reuse mature existing resources wherever possible and add only the project-specific logic that TeXWeave actually needs.

Core principle:

> **Prefer integration over reinvention.**

v0.2.5 should provide reliable, context-aware, project-aware completion while keeping the implementation lightweight enough to remain a foundation release.

---

## 2. Scope

The completion system in v0.2.5 should cover the following categories:

1. LaTeX command completion
2. Environment completion
3. Custom command and custom environment completion
4. Label/reference completion
5. Citation completion
6. Project file completion
7. Context-aware filtering
8. Basic ranking and sorting

AI-generated inline completion is explicitly out of scope for this release.

---

## 3. Main Features

### 3.1 LaTeX Command Completion

Support common LaTeX commands such as:

```latex
\section
\subsection
\textbf
\emph
\frac
\sqrt
\sum
\int
\mathbb
```

Requirements:

- Prefix matching
- Basic fuzzy matching
- Snippet insertion where appropriate
- Support both text-mode and math-mode commands
- Avoid manually maintaining a large command list inside TeXWeave

Recommended implementation:

- Use Monaco Editor's completion API if Monaco is the current editor backend
- Prefer TexLab/LSP completion when available
- Use existing LaTeX/KaTeX command data only as fallback/static data
- Do not build a full LaTeX command database manually

---

### 3.2 Environment Completion

Inside:

```latex
\begin{
```

suggest environments such as:

```text
document
equation
align
figure
table
itemize
enumerate
theorem
lemma
proof
```

For selected environments, insert a full snippet:

```latex
\begin{environment}
    $0
\end{environment}
```

Requirements:

- Built-in environments
- Package-provided environments when available
- Project-defined environments
- Project-defined theorem environments

Recommended implementation:

- Monaco snippet/completion support
- TexLab/LSP as the primary source for general LaTeX environments
- TeXWeave ProjectIndex for project-specific environments

---

### 3.3 Custom Command and Environment Completion

TeXWeave should recognize definitions such as:

```latex
\newcommand{\E}{\mathbb{E}}
\renewcommand{\vec}[1]{\mathbf{#1}}
\newenvironment{myenv}{...}{...}
\newtheorem{theorem}{Theorem}
```

The same applies to definitions located in local `.sty` files.

Example:

```latex
\newcommand{\Var}{\operatorname{Var}}
```

Typing:

```latex
\V
```

should suggest:

```text
\Var
```

Requirements:

- Scan current project
- Include referenced `.sty` files
- Include definitions from project resource presets where relevant
- Update the index after relevant file changes

Recommended implementation:

1. Use TexLab workspace information where sufficient
2. Otherwise maintain a lightweight TeXWeave `ProjectIndex`
3. Avoid implementing a complete TeX parser solely for this feature

The ProjectIndex only needs to identify a limited set of declaration forms required by TeXWeave.

---

## 4. Label and Reference Completion

Inside commands such as:

```latex
\ref{}
\eqref{}
\autoref{}
```

suggest available project labels.

Example:

```latex
\ref{thm:
```

may display:

```text
thm:consistency
Theorem 3.1 · sections/theory.tex

thm:asymptotic
Theorem 4.2 · sections/asymptotic.tex
```

Requirements:

- Search labels across the whole project
- Display label key
- Display useful location metadata when available
- Prioritize equation labels inside `\eqref{}`
- Support cross-file references

Recommended implementation:

- Prefer TexLab/LSP workspace information
- Maintain a fallback label index in TeXWeave if needed
- Reuse existing project file parsing/indexing infrastructure

---

## 5. Citation Completion

Inside:

```latex
\cite{}
```

suggest citation keys from project bibliography files.

Example:

```text
chen2006
Chen & Fan (2006)
Estimation of copula-based semiparametric time series models
```

Requirements:

- Support `.bib`
- Support BibTeX and BibLaTeX workflows where possible
- Support multiple citations:

```latex
\cite{chen2006,pat
```

- Show metadata such as:
  - citation key
  - author
  - year
  - title

Recommended implementation:

- Reuse TexLab bibliography support where possible
- Use an existing BibTeX/BibLaTeX parser if richer metadata is required
- Do not implement a full BibTeX engine manually

---

## 6. Project File Completion

The following commands should support file-aware completion:

```latex
\input{}
\include{}
\includegraphics{}
\bibliography{}
\addbibresource{}
```

Expected filtering:

| Command | Suggested files |
|---|---|
| `\input{}` | `.tex` |
| `\include{}` | `.tex` |
| `\includegraphics{}` | image files |
| `\bibliography{}` | `.bib` |
| `\addbibresource{}` | `.bib` |

Requirements:

- Use the current project file tree
- Prefer relative project paths
- Respect the current file location
- Avoid suggesting irrelevant file types

Recommended implementation:

- Reuse the existing TeXWeave project/file-tree index
- No language model is needed
- No full LaTeX parser is needed

---

## 7. Context-Aware Completion

Completion should depend on cursor context.

Examples:

### Environment context

```latex
\begin{
```

Show only environments.

### Citation context

```latex
\cite{
```

Show only bibliography entries.

### Reference context

```latex
\ref{
```

Show only labels.

### Graphics context

```latex
\includegraphics{
```

Show only compatible graphics files.

### General command context

```latex
\sec
```

Show general LaTeX commands.

Implementation strategy:

Create a lightweight `CompletionContextAnalyzer` that examines text immediately before the cursor and identifies the active completion mode.

Suggested modes:

```ts
type CompletionMode =
  | "command"
  | "environment"
  | "reference"
  | "citation"
  | "tex-file"
  | "image-file"
  | "bib-file"
  | "unknown";
```

This layer should remain small and deterministic.

---

## 8. Completion Ranking

v0.2.5 only needs a simple ranking strategy.

Recommended priority:

```text
1. Exact project-defined match
2. Exact prefix match
3. Project-specific definitions
4. Recently used items
5. Common built-in LaTeX items
6. Fuzzy matches
```

Implementation:

- Prefer the editor's built-in filtering/ranking capabilities
- Use Monaco `sortText`, `filterText`, `preselect`, and related completion fields
- Do not build a machine-learning ranking system

---

## 9. Recommended Architecture

```text
Monaco Editor
      │
      ▼
CompletionController
      │
      ├── CompletionContextAnalyzer
      │
      ├── TexLab / LSP Provider
      │      ├── commands
      │      ├── environments
      │      ├── labels
      │      ├── citations
      │      └── workspace semantics
      │
      ├── TeXWeave ProjectIndex
      │      ├── custom commands
      │      ├── custom environments
      │      ├── theorem definitions
      │      ├── labels
      │      ├── local .sty definitions
      │      └── project files
      │
      └── SnippetProvider
             ├── environments
             ├── common commands
             └── future user snippets
```

## 10. Responsibility Split

### TexLab / LSP should handle

Prefer TexLab or another mature LSP implementation for generic LaTeX intelligence:

- General LaTeX commands
- Standard environments
- Cross-file workspace awareness
- Label/reference information
- Citation information
- Language-server diagnostics
- Future hover/go-to-definition support

TeXWeave should not duplicate these features unless necessary.

---

### TeXWeave ProjectIndex should handle

TeXWeave-specific project semantics:

- Project-local commands
- Project-local environments
- `.sty` files
- TeXWeave resource presets
- Project file tree
- TeXWeave-specific metadata
- Future block/dependency information

This index should gradually become a reusable semantic layer for later versions.

---

## 11. Use Existing Resources First

The implementation should actively prefer existing mature resources.

### Editor layer

Prefer:

- Monaco Editor Completion API
- Monaco snippet insertion
- Monaco suggestion UI
- Monaco filtering and ranking

Do not build a custom autocomplete popup unless there is a strong product reason.

### LaTeX language intelligence

Prefer:

- TexLab
- Language Server Protocol

Do not implement a complete LaTeX parser only to support completion.

### Command data

Prefer:

- TexLab-provided completion data
- Existing LaTeX command datasets
- KaTeX-supported command data as supplemental fallback

Do not manually create and maintain thousands of command definitions.

### Bibliography

Prefer:

- TexLab bibliography support
- Existing BibTeX/BibLaTeX parsing libraries

Do not write a complete BibTeX parser unless unavoidable.

---

## 12. Suggested Implementation Phases

### Phase 1: Completion Infrastructure

Implement:

- `CompletionController`
- Monaco completion registration
- Context detection
- Basic result merging

No complex semantic parsing yet.

---

### Phase 2: Static and Project Completion

Implement:

- Common command completion
- Environment completion
- File completion
- Simple custom command scan
- Simple label scan

This produces a usable MVP even before full LSP integration.

---

### Phase 3: TexLab / LSP Integration

Add TexLab as the primary generic LaTeX intelligence source.

Use it for:

- command completion
- environment completion
- references
- citations
- workspace semantics

Keep TeXWeave fallback providers available where needed.

---

### Phase 4: ProjectIndex Integration

Merge TeXWeave-specific information into completion results:

- `.sty`
- local macros
- local theorem definitions
- project resource presets
- project files

Deduplicate results from multiple providers.

---

### Phase 5: Polish

Improve:

- ranking
- detail text
- icons/categories
- documentation preview
- insertion behavior
- refresh performance
- index invalidation

---

## 13. Non-Goals for v0.2.5

The following features should not be implemented in this release:

- AI-generated inline completion
- Ghost-text prediction
- Natural-language paragraph generation
- Full TeX AST implementation
- Custom autocomplete UI from scratch
- Full BibTeX engine
- ML-based completion ranking
- Automatic theorem/proof generation
- Complex package documentation assistant
- Full user snippet management system
- AI agent integration

These should remain future extensions.

---

## 14. Acceptance Criteria

v0.2.5 is complete when the following scenarios work reliably.

### Commands

Typing:

```latex
\sec
```

offers:

```text
\section
```

### Environments

Typing:

```latex
\begin{the
```

offers available theorem environments.

### Custom commands

If the project contains:

```latex
\newcommand{\Var}{\operatorname{Var}}
```

typing:

```latex
\Va
```

offers:

```text
\Var
```

### References

If the project contains:

```latex
\label{thm:main}
```

then:

```latex
\ref{thm:
```

offers:

```text
thm:main
```

### Citations

If the project bibliography contains:

```bibtex
@article{chen2006, ...}
```

then:

```latex
\cite{che
```

offers:

```text
chen2006
```

### Files

Typing:

```latex
\input{sec
```

offers matching `.tex` files.

Typing:

```latex
\includegraphics{fig
```

offers matching image files.

## 15. Future Extension Points

The completion architecture should intentionally leave room for later providers.

Example:

```ts
interface CompletionProvider {
  provideCompletion(
    context: CompletionContext
  ): Promise<CompletionItem[]>;
}
```

Possible future providers:

```text
LatexBuiltinProvider
TexLabProvider
ProjectProvider
BibliographyProvider
SnippetProvider
AICompletionProvider
```

This allows future AI completion to be added without replacing the deterministic completion system.

---

## 16. Relation to Future AI Features

v0.2.5 should not implement AI, but its architecture should prepare for it.

The same project index used today for:

```latex
\ref{}
\cite{}
\newcommand
```

can later provide structured context to AI.

Future AI context may include:

```text
current file
current section
selected text
labels
citations
custom commands
project structure
dependency graph
related theorem/lemma blocks
```

Therefore, v0.2.5 is not only an autocomplete release.

It establishes the first reusable semantic infrastructure for future:

- structural document understanding
- dependency graph features
- ChatGPT/Codex integration
- AI-assisted editing
- project-aware research assistance

---

## 17. Release Summary

### v0.2.5 — Basic Completion

Main additions:

- LaTeX command completion
- Environment completion
- Custom command/environment completion
- Label/reference completion
- Citation completion
- Project file completion
- Context-aware filtering
- Basic completion ranking
- Initial reusable project semantic index
- Architecture prepared for LSP and future AI providers

Implementation principle:

> **Reuse mature editor, LSP, LaTeX, and bibliography infrastructure wherever possible. TeXWeave should focus on project-specific semantics rather than rebuilding solved problems.**
