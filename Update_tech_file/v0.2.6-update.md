# TeXWeave v0.2.6 Update Plan

## 1. Version Goal

v0.2.6 introduces the first version of **spell checking** for TeXWeave.

The primary target is English, while the architecture should allow other languages to work automatically when the operating system or spell-check backend supports them.

Core principle:

> **Reuse mature spell-checking and language-detection resources wherever possible. TeXWeave should focus on LaTeX-aware text extraction, editor integration, and user control.**

This release should remain lightweight and infrastructure-oriented.

---

## 2. Main User Experience

Spell checking is enabled by default.

The bottom status bar should contain a small spell-check control such as:

```text
Spell: Auto (EN)
```

Clicking it opens a language menu:

```text
✓ Auto (English detected)

English (US)
English (UK)
Japanese
German
French
...

Disable Spell Check
```

The behavior is:

```text
AUTO
 ├─ language detected with sufficient confidence
 │      → use detected language
 │
 └─ detection uncertain / insufficient text
        → fall back to English

MANUAL
 └─ always use the selected language
    until the user explicitly switches back to Auto

DISABLED
 └─ no spell checking
```

Manual language selection must disable automatic language switching.

## 4. LaTeX-Aware Text Extraction

Spell checking must not run directly over the entire `.tex` source.

For example:

```latex
\begin{theorem}
Suppose $X_t \in \mathbb{R}$ satisfies Assumption~\ref{ass:mixing}.
\end{theorem}
```

The spell checker should mainly inspect:

```text
Suppose
satisfies
Assumption
```

while ignoring LaTeX syntax and non-natural-language regions.

### 4.1 Text that should normally be checked

Examples:

- ordinary prose
- section titles
- subsection titles
- captions
- text inside `\textbf{}`
- text inside `\emph{}`
- text following `\item`
- theorem/lemma/proof prose

### 4.2 Text that should normally be ignored

Examples:

```latex
\command
\label{}
\ref{}
\eqref{}
\autoref{}
\cite{}
\url{}
```

Also ignore:

- math mode
- display equations
- equation/align-style environments
- file paths
- bibliography keys
- command names
- URLs
- code-like content
- comments by default

### 4.3 Preserve Source Mapping

The extractor must preserve the relationship between extracted natural-language text and the original `.tex` source.

Recommended structure:

```ts
interface TextSegment {
  text: string;
  sourceStart: number;
  sourceEnd: number;
}
```

Prefer extracting continuous source segments rather than producing one fully rewritten plain-text document.

This makes it easy to map spell-check results back to Monaco editor positions.

## 5. Automatic Language Detection

Language detection should be implemented as a separate service.

Recommended interface:

```ts
interface LanguageDetector {
  detect(text: string): {
    language: string | null;
    confidence: number;
  };
}
```

Do not implement a custom language-detection algorithm unless necessary.

Prefer a mature existing library based on statistical or n-gram language identification.

### 5.1 Detection Input

Detection should operate only on natural-language text extracted from the LaTeX document.

Do not include:

- formulas
- commands
- labels
- citations
- paths

A limited sample is sufficient, for example several hundred to a few thousand natural-language characters.

### 5.2 Detection Rules

Recommended logic:

```text
Extract natural-language sample
        ↓
Enough text?
   ├─ No  → keep current detection / English fallback
   └─ Yes
        ↓
Run language detection
        ↓
Confidence high enough?
   ├─ Yes → use detected language
   └─ No  → English fallback
```

Avoid language switching on very short text.

Example:

```text
Proof.
```

should not trigger a language change.

### 5.3 When to Re-detect

Do not detect language on every keystroke.

Suggested triggers:

- opening a file
- switching files
- major document changes
- after a short idle period
- manually returning to Auto mode

## 6. Language State

Recommended state model:

```ts
type SpellLanguageMode =
  | {
      mode: "auto";
      detectedLanguage: string;
    }
  | {
      mode: "manual";
      language: string;
    }
  | {
      mode: "disabled";
    };
```

### Auto Mode

Example:

```text
Spell: Auto (EN)
```

The detected language may change as the document changes.

If detection fails or is uncertain:

```text
fallback → English
```

### Manual Mode

Example:

```text
Spell: EN-US
```

Automatic detection must no longer change the active language.

### Disabled Mode

Example:

```text
Spell: Off
```

No spell-check work should be scheduled.

## 7. Spell Check Provider Abstraction

Do not couple editor logic directly to one operating-system API.

Create a provider abstraction:

```ts
interface SpellCheckProvider {
  getAvailableLanguages(): Promise<string[]>;

  check(
    text: string,
    language: string
  ): Promise<SpellError[]>;

  suggest(
    word: string,
    language: string
  ): Promise<string[]>;

  addToDictionary(
    word: string
  ): Promise<void>;

  ignore(
    word: string
  ): Promise<void>;
}
```

Suggested error representation:

```ts
interface SpellError {
  offset: number;
  length: number;
  word: string;
  suggestions?: string[];
}
```

This allows the backend to be replaced later without changing Monaco integration.

Possible implementations:

```text
ElectronSpellCheckProvider
WindowsSpellCheckProvider
HunspellProvider
MacSpellCheckProvider
FutureGrammarProvider
```

## 8. Preferred Existing Resources

### 8.1 Electron / Chromium

If TeXWeave is running on Electron, prefer Electron's existing spell-checking facilities first.

Electron already provides access to:

- available spell-check languages
- language selection
- spelling suggestions
- dictionary operations

This avoids implementing a new dictionary system.

The exact integration should be evaluated against Monaco because Monaco is not a normal HTML text input.

If Chromium's visual spell-checking cannot be used directly inside Monaco, TeXWeave should still reuse the spell-check backend while rendering errors itself.

---

## 9. Windows Native Spell Checker

Windows provides a system spell-check API.

It can be used as an alternative provider when needed.

Conceptually:

```text
TeXWeave
   ↓
Windows Spell Checker
   ↓
misspelled ranges
suggestions
dictionary actions
```

The Windows implementation can use the system's installed language resources.

Advantages:

- no custom dictionary maintenance
- system-level language support
- suggestions
- ignore/add-to-dictionary behavior

Because the API is native/COM-based, it should sit behind a thin bridge rather than being called directly from React code.

Recommended architecture:

```text
React / TypeScript
      ↓
SpellCheckProvider
      ↓
native bridge
      ↓
Windows Spell Checker
```

This should be a fallback or platform-specific provider, not something the rest of TeXWeave depends on directly.

---

## 10. Multi-Language Support

Although English is the primary supported language in v0.2.6, the system should discover available languages dynamically.

Example:

```text
en-US
en-GB
de-DE
fr-FR
ja-JP
...
```

The language menu should preferably show only languages available through the active spell-check provider.

Recommended product policy for v0.2.6:

> English is officially supported. Other languages are available when supported by the active system spell-check backend.

Do not promise identical quality across languages.

---

## 11. Monaco Editor Integration

Spell-check results should be rendered through Monaco decorations rather than relying entirely on browser-native spell-check UI.

Example:

```ts
{
  range,
  options: {
    inlineClassName: "spell-error"
  }
}
```

Possible CSS:

```css
.spell-error {
  text-decoration-line: underline;
  text-decoration-style: wavy;
}
```

The exact visual style should follow TeXWeave's editor design.

Benefits:

- full control over which LaTeX regions are checked
- precise source mapping
- consistent visuals
- easy future integration with grammar checking

---

## 12. Context Menu

Right-clicking a misspelled word should provide:

```text
receive
received
receiver
────────────
Ignore
Add to Dictionary
```

Recommended actions:

### Suggestion

Replace only the selected misspelled range.

### Ignore

Ignore the word for the current editing session.

### Add to Dictionary

Add the word through the underlying system/provider dictionary mechanism where supported.

This is especially important for scientific terminology, names, abbreviations, and domain-specific vocabulary.

Examples:

```text
copula
semiparametric
Ljung
Imhof
```

## 13. Performance

Spell checking must be incremental.

Do not do:

```text
every keypress
→ check entire document
```

Recommended behavior:

```text
edit
 ↓
debounce
 ↓
find affected text segment / paragraph
 ↓
re-extract natural-language text
 ↓
spell-check only affected region
 ↓
update decorations
```

Suggested debounce:

```text
300–500 ms
```

On initial file open, a full-document scan is acceptable.

After that, prefer incremental updates.

Possible caching:

```ts
Map<TextSegmentHash, SpellError[]>
```

---

## 14. Project and Scientific Vocabulary

Scientific writing produces many valid words that general dictionaries may not recognize.

v0.2.6 should at minimum support:

- Ignore
- Add to Dictionary

Future versions may add:

```text
Global Dictionary
Project Dictionary
```

A project dictionary would allow paper-specific terminology without permanently changing the global system dictionary.

This is not required for the first implementation.

---

## 15. Spell Check vs Grammar Check

v0.2.6 should only implement spelling.

Example:

```text
recieve
```

is a spelling error.

Example:

```text
He go to school.
```

is a grammar error.

Grammar checking belongs to a later version.

The architecture should nevertheless allow a future:

```text
GrammarProvider
```

to reuse:

- LaTeX text extraction
- language detection
- source mapping
- Monaco decorations

---

## 16. Recommended Implementation Phases

### Phase 1: Spell-Check Infrastructure

Implement:

- `SpellCheckService`
- `SpellCheckProvider`
- spell-check state
- Monaco decoration support

Use English only initially.

### Phase 2: LaTeX Text Extraction

Implement:

- natural-language segment detection
- math exclusion
- command exclusion
- citation/reference exclusion
- source-offset mapping

This is the most important TeXWeave-specific part.

### Phase 3: Spell Backend Integration

Prefer an existing backend:

1. Electron/Chromium spell-checking capability
2. Windows native spell-check API if required
3. other mature providers only if needed

Avoid maintaining a custom dictionary.

### Phase 4: Suggestions and Context Menu

Implement:

- suggestions
- replacement
- Ignore
- Add to Dictionary

### Phase 5: Automatic Language Detection

Add:

- mature language-detection library
- confidence threshold
- minimum text length
- English fallback
- status-bar display

### Phase 6: Language Selection UI

Implement status-bar control:

```text
Spell: Auto (EN)
```

and language menu.

Manual selection must lock the selected language until the user switches back to Auto.

### Phase 7: Performance Optimization

Add:

- incremental checking
- debounce
- affected-region detection
- caching
- cancellation of stale checks

---

## 17. Non-Goals for v0.2.6

Do not implement:

- grammar checking
- AI rewriting
- AI-generated correction explanations
- custom dictionary engine from scratch
- custom language-detection model
- full per-sentence multi-language detection
- automatic rewriting of spelling errors
- sophisticated project dictionaries
- style checking
- academic writing quality scoring

---

## 18. Acceptance Criteria

v0.2.6 is complete when the following scenarios work reliably.

### Basic English Check

Given:

```latex
This is a recieve test.
```

TeXWeave marks:

```text
recieve
```

as misspelled.

### LaTeX Filtering

Given:

```latex
\begin{theorem}
Suppose $X_t \in \mathbb{R}$ satisfies \ref{ass:mixing}.
\end{theorem}
```

TeXWeave does not incorrectly flag:

```text
begin
theorem
mathbb
ref
ass:mixing
```

as spelling errors.

### Suggestions

Right-clicking:

```text
recieve
```

shows appropriate suggestions such as:

```text
receive
```

### Ignore

Selecting:

```text
Ignore
```

removes the warning for the current session.

### Add to Dictionary

A scientific term can be added to the provider/system dictionary when supported.

### Automatic Language Mode

The status bar shows something similar to:

```text
Spell: Auto (EN)
```

for an English document.

If language detection is uncertain:

```text
fallback → English
```

### Manual Language Mode

Selecting:

```text
English (UK)
```

changes the status to:

```text
Spell: EN-GB
```

and disables automatic switching.

### Disable

Selecting:

```text
Disable Spell Check
```

removes spelling decorations and stops new spell-check tasks.

The v0.2.6 infrastructure should later support:

```text
GrammarProvider
StyleProvider
AcademicWritingProvider
AIWritingAssistant
ProjectDictionary
Per-block language detection
```

The important reusable components are:

```text
LatexTextExtractor
LanguageDetector
SourceMapping
DecorationManager
Provider abstraction
```

These should remain independent from the specific spell-check backend.

### v0.2.6 — Spell Checking

Main additions:

- English spell checking
- automatic language detection
- English fallback
- manual language selection
- spell-check disable control
- status-bar language indicator
- LaTeX-aware natural-language extraction
- source-offset mapping
- Monaco red-wave decorations
- correction suggestions
- Ignore
- Add to Dictionary
- incremental checking
- provider-based architecture
- automatic discovery of system-supported languages

Implementation principle:

> **Use mature system and framework spell-checking capabilities wherever possible. TeXWeave should implement the LaTeX-aware layer, not reinvent dictionaries or spelling algorithms.**
