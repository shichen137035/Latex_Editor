# 文档文本版本与结构工作集

适用版本：0.6.4 开发仓库，2026-10-08。

## 两个明确的读视图

| 视图 | 文本来源 | 结构存储 | 使用者 |
| --- | --- | --- | --- |
| 已保存视图 | 项目磁盘文件 | `.texweave/structure.json` | CLI、编译及独立文件服务 |
| 编辑工作集 | 已保存文件 + 当前会话的未保存 TeX buffer | 主进程内存中的结构分支 | 桌面 structure、blockGraph、relations |

桌面结构服务通过 [WorkingDocumentFiles](../packages/application/src/working-documents.ts) 读取工作集。文本、源码范围、查询索引和块身份沿用同一个读视图，不会再用磁盘文字解释未保存的范围。

AI 工作副本继续创建自己的文件服务和块服务，解析其自身文件。它可以使用调用时传入的上下文文本，但不会直接读取桌面会话的内存分支。`saved` 表示在该服务自己的文件根目录中已保存，不是全局共享的版本。

## 版本契约

`documents.sync(projectId, input)` 输入包含：

- `sessionId`：一个编辑器会话的身份，绑定创建它的 Electron WebContents。
- `revision`：同一会话严格递增的快照编号。
- `files`：当前打开的 TeX 文件，包含 `fileId`、buffer `content` 和编辑器确认过的磁盘基线 `savedContent`。
- `rangeChanges`：可选的实际编辑事务记录。后端重放并验证起点、终点及插入文字，只映射尚未接受的事务，保证多处编辑不会误移中间的自定义块。

后端先验证全部文件基线，再在共享项目锁内映射自定义块范围、解析、reconcile 和切换工作集。正文、文件指纹、源版本标记及语义 ID 映射属于同一次更新。较旧、重复、其他会话或已关闭会话的请求不会被接受。前端同样忽略过期响应。

不再向 renderer 暴露未带版本的 `blockGraph.reconcileParsedBlocks` / `mapUserBlockRanges` IPC。前端不提交自己计算的持久化范围；这些规则由应用服务处理。底层图方法仍是核心算法及测试的内部接口。

`DocumentTextVersion` 描述实际文本版本：

```ts
{ kind: "saved", fingerprint: string }
{ kind: "working", fingerprint: string, sessionId: string, revision: number }
```

`DocumentStructure.files`、`get_block`、`get_block_source` 会报告文本版本。它与 `DocumentBlock.revision` 分工不同：前者标识整个文件的读视图，后者用于块内容的乐观并发检查。

## 保存、放弃和退出

1. **编辑**：未保存文本和派生结构保存在内存。此时对图和语义的修改也留在工作分支，避免把暂存范围写入磁盘。
2. **保存一个文件**：校验保存的是当前 buffer，磁盘仍匹配它的基线，再写入源文件；若其他文件仍未保存，工作图继续留在内存。
3. **全部未保存文件已保存**：提交工作图到磁盘，其文件源版本必须全部为 `saved`。复杂派生索引可保留 `indexDirty`，结构 API 下一次查询按已保存文字刷新。
4. **放弃某个文件**：恢复该文件的已保存块、范围和相关关系，同时保留其他文件的工作范围及语义；重新解析其余工作内容，避免重复应用范围偏移。
5. **退出项目/关闭窗口**：释放会话、内存图、增量解析缓存和结构服务缓存。未提交的图修改随未保存工作集放弃；磁盘文件保持已经保存的内容。渲染器崩溃也有释放路径。

项目离开逻辑会等待保存和会话释放完成后再切换页面。React StrictMode 的 effect 重放不会误关正在使用的会话。窗口监听在正常关闭会话后解除，避免反复打开项目累积监听器。

因为图包含跨文件关系，目前以项目工作集作为图提交单位。保存单个源文件不等于提交仍依赖其他未保存文件的全部图元数据。

## 冲突和失败

- 外部修改磁盘文本，或保存时发现 buffer 已有更新：返回 `DOCUMENT_VERSION_CONFLICT`，不覆盖不同版本。
- 已保存元数据在工作期间被其他入口改变：提交前检查其基线，拒绝静默覆盖其他入口的修改。
- 对未保存文件调用写入磁盘的块源码 API，或移动/删除其文件、所在目录：返回 `UNSAVED_DOCUMENT`，先保存后再操作。读取块内容、查看关系和本地预览编辑继续可用。
- 源文件已保存，但结构元数据写入失败：报告失败并保留可重试的工作图；重试使用实际已保存的新基线，不假装整体保存成功。
- 即使磁盘结构元数据损坏，关闭工作集仍能释放内存；不会借关闭操作覆盖损坏文件。

文件系统写入继续沿用已有原子替换机制。项目锁协调应用内部操作，外部程序不受这把锁控制，因此文件基线检查仍然必需。

## 增量和缓存

增量算法已移到 [editor-core/preview/incremental.ts](../packages/editor-core/src/preview/incremental.ts)，renderer 保留薄导出入口，后端工作集直接复用同一实现。

- 内容及配置不变，复用解析结果。
- 安全的普通文本编辑，使用增量路径。
- 结构变化、配置变化或无法证明安全的编辑，完整重解析该文件。
- reconcile 使用当前 `parserId`，同时允许预览节点保留稳定的交互 ID，避免偏移后语义映射失配。
- 搜索控制器只处理显示与筛选，不再额外解析一份 canonical 结构或维护独立的范围更新队列。
- 查询缓存键包含文本视图及解析配置，不能只凭结构 revision 判断缓存有效，防止从工作分支返回已保存视图时误用旧索引。

这次不宣称消除了全部项目级解析成本：搜索仍有进一步按文件缓存的空间，结构 API 的 refresh 也仍检查项目文件及 aux 编号。该项属于下一轮性能优化。
