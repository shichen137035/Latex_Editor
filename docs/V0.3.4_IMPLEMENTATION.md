# TeXWeave v0.3.4 implementation roadmap

The implementation is split at architectural boundaries so UI work never owns
or duplicates semantic validation.

## Phase 1 — semantic foundation (implemented)

- Block origin, role, capabilities, source range and conflict/orphan state.
- Laminar range validation for User Blocks, including Virtual Blocks.
- Range-derived containment and deterministic child reparenting on deletion.
- One RelationValidator for self-loop, Virtual endpoint, reverse edge and cycle.
- Duplicate relations are no-ops; cycles are warnings and remain writable.
- Cycle-safe prerequisite/consequence/both neighborhood projection.
- Project-local structural Undo/Redo, separate from Monaco text history.
- `.texweave/structure.json` persistence with legacy snapshot migration.
- Main-process, preload and renderer contracts for all Phase 1 operations.

## Phase 2 — parser reconciliation (implemented)

- Environment Block UUID reconciliation by binding, unique label, stable
  content fingerprint and sibling context.
- Debounced editor-transaction mapping for persistent User Block ranges.
- Unresolved Environment endpoints become orphaned; their relations remain.
- Partial overlaps introduced by source edits mark User Blocks conflicted.
- Preview parse IDs remain transient and map to semantic UUIDs through the
  main-process persistence boundary.

## Phase 3 — relation workflow UI (implemented)

- Selection-first User Block creation is implemented for the toolbar,
  configurable shortcut and source/Preview context menus. Partial overlaps use
  a shared Expand/Trim boundary repair flow and open the Block Inspector.
- A shared snapshot projection keeps document ordering, containment, relation
  direction and candidate state consistent across all relation surfaces.
- The left Relation browser has independent expand/focus/locate controls,
  hierarchy/type/origin/label/search filters, temporary filter expansion and
  Dim/Hide behavior.
- Preview headers expose focus/add/remove controls. Both mode uses an explicit
  prerequisite/consequence chooser and all writes use the backend validator.
- Global and focused Relation Inspector states include structural Undo/Redo,
  direct prerequisite/consequence lists and relation removal.
- Focus Back history remains navigation-only; Ctrl+Z is routed to structural
  history only outside Monaco and form controls.

## Phase 4 — relation graph (implemented)

- Full and focused Display Graph views use the backend's cycle-safe
  neighborhood projection.
- Direction, BFS depth, fit and zoom controls are available without mutating
  the Semantic Graph.
- A dedicated Web Worker performs a stable left-to-right layered layout. Its
  message boundary intentionally permits replacing the lightweight layout with
  ELK without changing renderer state or graph interactions.
- Nodes support selection, double-click focus switching and Preview location.
