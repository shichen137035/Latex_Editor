# 预览滚动稳定性诊断（2026-10-09）

## 复现

使用独立临时项目，生成 160 个章节，每章包含文字、图片和 8 行表格。每次图片解析故意延迟 180ms，以模拟磁盘读取或 PDF 解码。先定位到文档后部，再连续向上滚动。

原实现的回归探针捕获了约 460px 的内容偏移；部分滚动步骤的 `scrollTop` 反向增加。修复后以可见内容叶节点为锚点，实测最大偏移约 0.27px。原生鼠标滚轮和快速变速滚轮均未观察到可见反向移动；快速测试确认实际触发了 14 次加速处理。数字是该 Windows/Electron 测试场景的结果，不代表所有设备与文档的统一上限。

运行：

```sh
npm run desktop:build
node apps/desktop/scripts/run-electron-check.mjs preview-scroll
```

## 原因与修复

- 原先浏览器自动滚动锚定与虚拟列表手动 `scrollTop` 补偿同时工作，可能重复调整位置。预览现在关闭浏览器自动锚定，由虚拟列表统一维护可见内容位置。
- 原先每一行独立测量、立即通知 React 并按高度差补偿。父、子虚拟行可能报告同一次布局变化，重复补偿或产生中间画面。现在每帧批量提交高度，按一个可见叶节点的实际 DOM 位移统一补偿。
- 锚点补偿保留用户在测量期间的滚动增量，避免把持续向上的手势当作需要恢复的旧位置；大幅显式跳转会建立新锚点。
- 图片虚拟行重新挂载时，原先先收缩成加载占位，再随图片撑开。现在加载期间保留已测量高度，加载完成或失败后重新测量；图片加载、DOM 内容替换与 ResizeObserver 均进入同一个批量更新流程。
- 实际高度即便与初始估算相同，也会保存，避免后续使用新估算覆盖已知布局。
- 离开文件时取消待处理帧、清理锚点及观察器，防止前一文件的补偿影响后一文件。

这套处理保留虚拟列表、滚轮加速及现有图片/表格编辑机制，没有关闭虚拟化。

## 验证

- 72 个单元测试文件、516 项测试通过，包括用户滚动增量、嵌套行、显式跳转和逐帧批量测量的新回归。
- 延迟图片与表格混合滚动测试通过，覆盖普通原生滚轮和实际触发的变速滚轮。
- 引用跳转、返回/前进、文件位置恢复和跳转前提交局部源码草稿通过界面回归。
- 表格独立编辑窗口、内部滚轮与滚动条、浮动工具栏通过界面回归。
- 1400 个章节的大文档保持 17–21 个已挂载内容节点；700 段落与 700 列表项的嵌套场景保持 44 个虚拟行，引用仍能跳转到未挂载位置。
- 桌面构建、类型检查、lint 和简体中文语言检查通过。大文档脚本同时更新了过时的标题选择器，并在替换测试文档前正常释放编辑会话。
