# 界面语言检查

界面文案统一维护在 `apps/desktop/src/renderer/i18n/locales/*.json`。英文是键的基准；原生窗口和渲染界面使用同一份语言文件。构建时会将副本放到主进程输出目录。

检查简体中文：

```sh
npm run i18n:check -- --locale zh-CN --details
```

检查所有语言，或输出机器可读报告：

```sh
npm run i18n:check -- --details
npm run --silent i18n:check -- --json
```

报告按语言列出缺失键及英文原文、`{{变量}}` 不一致、额外键和仍与英文相同的文案。扫描同时检查未定义的翻译调用、JSX 文字、提示与无障碍标签、菜单描述、界面错误提示及原生窗口文案。缺失键、变量不一致、未定义键或固定界面文案会使命令返回非零状态。额外键和相同译文作为复核信息保留。

增加文案时，在英文和目标语言中添加相同的键，并通过 `t()` 调用。包含计数、名称或路径的提示使用完整句子和命名变量；不要拼接英文复数后缀。模块级选项保存翻译键，在渲染时取译文，避免切换语言后仍显示初始化时的文字。

语言选择统一使用 `LanguageSelect`。选项值是固定语言代码，选项名称固定为语言本名：English、日本語、简体中文、繁體中文、한국어、Français，不调用界面翻译。拼写检查的其他语言使用该语言自身的区域设置生成本名，无法识别时显示原代码。下拉框标签、说明和无障碍提示仍随界面语言翻译。

品牌名、真实键盘键名、文件名、LaTeX/CSS/XML 语法和用户输入不作为待翻译文案。检查器采用语法树扫描，数据驱动标签还需检查默认环境、预设和实际界面。自定义资源名和文献内容保留用户原文。外部编译日志与 AI 回答也保留原文。

应用版本不属于翻译目录。根 `package.json` 的 `version` 是唯一来源；主进程通过 `readAppInfo()` 读取，首页通过类型化的 `app.info()` IPC 显示。构建、安装记录和 AI 客户端也使用根包版本；不用维护语言文件中的版本号或 Vite 注入常量。

环境块和特殊命令的名称保存在各自定义的 `labels` 中，例如 `{ "en": "Theorem", "zh-CN": "定理" }`。管理器的名称语言下拉框默认选中当前界面语言；修改只写入所选语言，不改变内部 ID、LaTeX 名称或其他语言。内置翻译作为未覆盖语言的默认值。旧的单一自定义名称保留为英语回退名称。

常规设置中的“固定名称语言”默认开启，优先语言默认英语；关闭后优先当前界面语言。这是全局显示规则，两类管理器、预览、快速插入和关系界面共用。缺少优先语言名称时，按下拉框顺序寻找首个非空值：英语、日语、简体中文、繁体中文、韩语、法语；再尝试其他已保存语言，最终显示内部 ID。空白自定义名称不请求翻译目录，也不产生缺失键；新建自定义环境的 `labelKey` 为空。XML 使用 `<name locale="zh-CN" value="定理" />` 保留名称表，空条目也能往返。

语言回退仅用于保持不完整语言可用，不能代替补充目标语言的译文。目前完整检查基线为简体中文。
