# AI 附件缓存生命周期

0.6.4 开发仓库，2026-10-08。

## 所有权与存储

附件属于一个草稿，草稿绑定项目、独立 draft ID 和创建它的 Electron WebContents。每次切换会话创建新草稿；发送时自动创建的会话可接管当前草稿，避免第一次发送时附件被误删。

[AIAttachmentStore](../apps/desktop/src/main/ai/attachment-store.ts) 把附件保存为应用用户数据目录中 `ai/attachment-cache/<draft-id>/<attachment-id>/<name>` 的独立副本。缓存记录只有名称、大小、路径和生命周期状态，不保留粘贴文件或图片的 Buffer。文件选择也先生成不可变副本，后续修改原文件不会改变已选择的附件。

暂存目录与项目文件、AI 工作副本、对话历史分开。清理只删除应用创建的暂存副本，不删除用户选择的原文件。启动时清理这个专用目录的上次运行残留，并拒绝把符号链接作为缓存根目录。

## 释放时机

| 操作 | 缓存行为 |
| --- | --- |
| 点击附件删除按钮 | 通知后端移除附件，回收暂存文件及容量 |
| 切换会话/项目、关闭 AI 页面 | 关闭旧草稿，清理其附件 |
| 页面/窗口被销毁 | 主进程按窗口所有权关闭草稿，防止 renderer 没有完成清理 |
| 成功启动发送，或成功处理发送前的取消 | 消耗本次附件，释放草稿缓存；消息仍保留附件名称和大小 |
| 发送启动失败 | 释放复制租约，保留仍然打开的草稿副本，允许重试 |
| 程序退出 | 关闭仓库、排空暂存写入和清理队列，停止清理计时器 |
| 异常退出 | 下一次启动移除暂存目录残留 |

AI 工作副本中的附件遵循原有工作副本生命周期，仍可供当前 AI 读取和审查使用；释放草稿缓存不会删除它们。

## 并发与租约

发送在收集项目上下文之前获取附件租约。这样即使用户离开 AI 页面，已开始的发送也能完成附件复制。

- 复制或暂存期间被移除的附件会标记为待释放；最后一个引用结束后才删除文件。
- 删除状态下的附件不能被新的发送再次获取。
- 复制发生部分失败时，等待所有并行复制结束，再释放租约，不会提前删除其他正在复制的输入。
- 文件选择、剪贴板读取在草稿关闭后返回时，不能把附件重新加入新草稿。
- 移除、发送后释放及窗口销毁可能交错；重复释放不会重复扣减容量。
- 删除暂存文件失败时保留待清理记录和容量占用，每分钟重试，不把删除失败当作已经释放。

退出对供应商清理设置了最长 5 秒等待，防止无响应的供应商阻止退出；未完成的暂存清理可由下次启动恢复。

## 容量边界

| 限制 | 上限 |
| --- | --- |
| 单个附件 | 20 MB |
| 单个草稿 | 20 个附件，共 50 MB |
| 全部草稿的暂存文件 | 128 MB、200 个附件 |
| 同时打开的草稿 | 32 个 |

暂存前预留容量，失败时撤销预留，避免并行添加越过上限。正在使用、等待删除的副本也计入总容量。达到上限会报告错误，不静默驱逐其他活跃草稿。用户写作时间较长不会导致活跃草稿被定时清空。

这些是附件暂存容量限制，不是整个进程的内存上限；一次上传的 IPC 数据以及正在执行的文件写入仍会短暂占用内存。
