# 图片与表格诊断（2026-10-09）

本轮检查覆盖插入、项目资源解析、图片替换、浮动参数、caption/label、单元格编辑、结构操作、检查器状态、独立编辑窗口、环境配置和缓存生命周期。界面测试只操作临时项目及独立用户配置。

## 已复现并修复

| 问题 | 处理 |
| --- | --- |
| 图片和表格检查器使用简单正则读取 caption；嵌套命令、短 caption、星号及空参数可能识别或修改错误 | 预览、图片和表格共用 editor-core 的平衡参数解析和字段修改；保留可选参数与命令形式 |
| 父图片误取子图的 caption/label，注释中的示例也可能成为编辑目标 | 字段识别忽略注释，并按环境深度区分父、子范围；支持 `includegraphics*` |
| 修改空的 `[]` 可能把文本插入环境开头 | 使用参数边界定位，不再按参数文字搜索位置 |
| 删除带空格的图片尺寸选项会留下多余逗号 | 图片选项读取和修改共用分隔范围解析，保留其他选项及自定义值 |
| `tabular*` 将宽度误认为列格式 | 按宽度、可选位置、列格式的顺序解析，列操作保留宽度 |
| 异常行列数仍允许结构重建，额外单元格可能丢失 | 预览工具栏、侧栏与底层修改共用 `canRestructureTable`；仍允许定点单元格编辑 |
| 修改列对齐时丢失竖线边框并重写表体 | 只替换目标列格式，保留边框、空白和表体 |
| 带注释或自定义行距的表格重建可能丢失原格式 | 保守限制结构重建，保留源码与单元格编辑 |
| 整行、整列和 Tab 导航未同步检查器，提交与选择同一事件内可能携带旧源码 | 提交渲染后统一通知当前选择，并验证提交后返回单元格时检查器保留最新内容 |
| 图片数量减少后，检查器显示一个有效图片但仍用旧序号修改 | 取图、修改和替换使用同一个有效序号 |
| 同一图片通过不同引用路径读取时，缓存返回首次请求的路径信息 | 缓存复用字节，同时按当前请求返回路径与解析来源 |
| 图片字节及 PDF 缩略图缓存缺少容量与项目关闭清理 | 主进程接入项目缓存回收管理器；渲染进程在离开项目时清理缩略图；两级缓存均设数量与字符串容量上限 |
| PDF 图片取消渲染可能留下错误状态，PDF 与普通图片的宽度行为不一致 | 忽略取消后的错误，重新加载时复位；统一相对宽度，并限制缩略图渲染像素数 |

主进程图片缓存最多 64 项、约 1600 万字符串字符；PDF 缩略图最多 32 项、约 800 万字符串字符。实际内存还包括浏览器解码后的图像、画布与 PDF.js，不等同于上述字符串预算。回收后结束的异步图片读取不会重新填充已清理的缓存。

## 结构整理

- 合并预览、图片、表格中重复的平衡参数、caption/label 查找和最小修改实现。
- 合并图片选项分隔规则，避免读取与修改使用不同的语法边界。
- 集中表格结构编辑能力判断，避免侧栏与预览按钮规则不一致。
- 保留图片 I/O 缓存和 PDF 缩略图缓存两层：两者分别服务文件读取与渲染转换，职责不同。

## 保留的边界

预览不是完整的 LaTeX 执行器；复杂子图排版和自定义列宏仍存在显示限制，应通过源码与编译结果确认。当前图片内容解析主要在挂载、路径或 graphicspath 变化时更新，尚未提供针对外部同名图片内容变化的独立监听。PDF 缩略图取消与容量控制已经代码修正，本轮没有对大量真实 PDF 图片进行专项内存压力测量。
